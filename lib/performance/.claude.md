# Performance Module - Caching & Optimization

## 核心模式

### 響應緩存
```typescript
import { withCache } from '@/lib/performance/response-cache'

// 自動緩存函數結果
const customers = await withCache(
  'customers:list',
  300, // 5分鐘TTL
  async () => {
    return await prisma.customer.findMany()
  }
)
```

### 查詢優化
```typescript
import { optimizeQuery } from '@/lib/performance/query-optimizer'

// 自動添加索引提示和分頁
const optimized = optimizeQuery({
  model: 'customer',
  select: ['id', 'name', 'email'],
  where: { status: 'ACTIVE' },
  orderBy: { createdAt: 'desc' },
  take: 20
})
```

### 性能監控
```typescript
import { measurePerformance } from '@/lib/performance/monitor'

async function expensiveOperation() {
  const end = measurePerformance('operation-name')
  try {
    // 執行操作
    const result = await doSomething()
    return result
  } finally {
    end() // 記錄執行時間
  }
}
```

## 文件結構

- `response-cache.ts` - 響應級別緩存
- `query-optimizer.ts` - 查詢自動優化
- `monitor.ts` - 性能監控和指標

## 緩存策略

### 緩存層級
1. **應用緩存**: Node.js內存 (lru-cache)
2. **分佈式緩存**: Redis (生產環境)
3. **CDN緩存**: 靜態資源

### TTL配置
```typescript
const CACHE_TTL = {
  customers: 300,      // 5分鐘
  knowledgeBase: 600,  // 10分鐘
  proposals: 60,       // 1分鐘
  userProfile: 1800    // 30分鐘
}
```

### 緩存失效
```typescript
// 手動失效
await invalidateCache('customers:*')
await invalidateCache(`customer:${id}`)

// 自動失效（寫操作後）
await updateCustomer(id, data)
await invalidateCache(`customer:${id}`)
```

## 關鍵約定

1. **緩存鍵**: 使用命名空間 `resource:operation:id`
2. **讀多寫少**: 只緩存讀操作，寫操作失效緩存
3. **TTL適配**: 根據數據更新頻率設置TTL
4. **監控指標**: 記錄命中率、延遲、大小
5. **優雅降級**: 緩存失敗不影響業務邏輯

## 依賴關係

- `lru-cache` - 內存緩存
- `ioredis` - Redis客戶端
- `lib/monitoring` - 指標收集
