# Middleware - API Gateway & Request Interceptor

## 核心模式

### Next.js中間件
```typescript
// middleware.ts (根目錄)
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export async function middleware(request: NextRequest) {
  // 1. 認證檢查
  const token = request.cookies.get('accessToken')
  if (!token && isProtectedRoute(request.nextUrl.pathname)) {
    return NextResponse.redirect(new URL('/login', request.url))
  }

  // 2. 權限驗證
  const user = await verifyToken(token.value)
  if (!hasRoutePermission(user, request.nextUrl.pathname)) {
    return NextResponse.json({ error: 'Forbidden' }, { status: 403 })
  }

  // 3. 請求增強
  const response = NextResponse.next()
  response.headers.set('x-user-id', user.id.toString())

  return response
}

export const config = {
  matcher: ['/api/:path*', '/dashboard/:path*']
}
```

### 權限中間件
```typescript
// lib/middleware/permission-middleware.ts
export function requirePermission(resource: Resource, action: Action) {
  return async (request: NextRequest) => {
    const user = await authenticateRequest(request)
    if (!checkPermission(user, resource, action)) {
      throw AppError.forbidden(`No ${action} permission on ${resource}`)
    }
  }
}
```

## 中間件類型

### 1. 認證中間件
- 驗證JWT Token
- 刷新過期Token
- 重定向未登入用戶

### 2. 權限中間件
- RBAC權限檢查
- 路由級別控制
- 資源級別控制

### 3. 日誌中間件
- 請求日誌記錄
- 性能監控
- 錯誤追蹤

### 4. 速率限制
- IP限流
- 用戶限流
- API配額管理

## 關鍵約定

1. **執行順序**: 認證 → 權限 → 業務邏輯
2. **早期返回**: 驗證失敗立即返回，不執行後續邏輯
3. **請求增強**: 通過headers傳遞user信息給API
4. **匹配模式**: 使用 `matcher` 配置保護路由
5. **錯誤處理**: 中間件錯誤統一格式化

## 依賴關係

- `lib/auth` - 認證服務
- `lib/security` - 權限檢查
- `lib/performance` - 性能監控
