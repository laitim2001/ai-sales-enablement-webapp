# Workflow Module - Proposal State Machine

## 核心模式

### 狀態轉換
```typescript
// 狀態機定義
enum ProposalStatus {
  DRAFT = 'draft',
  IN_REVIEW = 'in_review',
  APPROVED = 'approved',
  REJECTED = 'rejected',
  SENT = 'sent'
}

// 狀態轉換驗證
const transitions = {
  draft: ['in_review'],
  in_review: ['approved', 'rejected', 'draft'],
  approved: ['sent'],
  rejected: ['draft'],
  sent: []
}

async function transitionStatus(
  proposalId: number,
  from: ProposalStatus,
  to: ProposalStatus,
  user: User
) {
  // 1. 驗證轉換合法性
  if (!transitions[from].includes(to)) throw new Error('Invalid transition')

  // 2. 權限檢查
  await checkTransitionPermission(user, from, to)

  // 3. 執行轉換
  await updateProposalStatus(proposalId, to)

  // 4. 觸發事件
  await notifyStakeholders(proposalId, to)
}
```

## 工作流規則

- **DRAFT**: 所有人可編輯，只能轉到IN_REVIEW
- **IN_REVIEW**: 只有Manager可審批
- **APPROVED**: 只能轉到SENT，不可退回
- **REJECTED**: 可退回DRAFT重新編輯
- **SENT**: 終態，不可更改

## 關鍵約定

1. **狀態驗證**: 使用 `transitions` 映射驗證
2. **權限分層**: DRAFT(REP) → REVIEW(MANAGER) → SENT(REP)
3. **版本記錄**: 每次重要修改創建新版本
4. **通知機制**: 狀態變化自動通知相關人員
