# API Utilities - Error Handling & Response Helper

## 核心模式

### 統一錯誤處理
```typescript
import { withErrorHandling } from '@/lib/api/error-handler'

export async function POST(request: NextRequest) {
  return withErrorHandling(async () => {
    // 業務邏輯
    // 任何拋出的錯誤會被自動捕獲和格式化
    const result = await doSomething()
    return NextResponse.json(result)
  })
}
```

### 請求驗證
```typescript
import { validateRequestBody, validateRequired } from '@/lib/api/error-handler'

// 驗證JSON格式
const body = await validateRequestBody<LoginRequest>(request)

// 驗證必填字段
validateRequired(body, ['email', 'password'], {
  email: 'Email',
  password: 'Password'
})
```

### 響應助手
```typescript
import { successResponse, errorResponse } from '@/lib/api/response-helper'

// 成功響應
return successResponse(data, { message: "創建成功" })

// 錯誤響應
return errorResponse("資源未找到", 404)
```

## 錯誤類型

```typescript
// 使用統一錯誤類
throw AppError.validation("Invalid email format")
throw AppError.unauthorized("Token expired")
throw AppError.forbidden("No permission")
throw AppError.notFound("Customer not found")
throw AppError.internal("Database error")
```

## 文件結構

- `error-handler.ts` - 錯誤處理中間件
- `response-helper.ts` - 響應格式化工具

## 響應格式

### 成功響應
```json
{
  "data": {...},
  "message": "操作成功",
  "timestamp": "2025-11-14T10:00:00Z"
}
```

### 錯誤響應
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid input",
    "details": {...}
  },
  "timestamp": "2025-11-14T10:00:00Z"
}
```

## 關鍵約定

1. **統一包裝**: 所有API handler使用 `withErrorHandling()`
2. **類型安全**: 使用 `validateRequestBody<T>()` 保證類型
3. **錯誤分類**: 使用 `AppError` 靜態方法創建錯誤
4. **日誌記錄**: 500錯誤自動記錄到日誌
5. **審計集成**: 錯誤響應可選觸發審計日誌

## 依賴關係

- `lib/security/audit-log` - 審計集成
