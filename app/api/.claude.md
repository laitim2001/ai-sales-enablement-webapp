# API Routes - Next.js 14 App Router

## 核心模式

### 標準路由處理
```typescript
// app/api/resource/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { withErrorHandling, validateRequestBody } from '@/lib/api/error-handler'

export async function POST(request: NextRequest) {
  return withErrorHandling(async () => {
    // 1. 認證
    const user = await authenticateRequest(request)

    // 2. 驗證
    const body = await validateRequestBody<T>(request)
    validateRequired(body, ['field1', 'field2'])

    // 3. 權限
    checkPermission(user, Resource.X, Action.CREATE)

    // 4. 業務邏輯
    const result = await businessLogic(body)

    // 5. 審計
    await auditLog.log({ action, userId: user.id })

    // 6. 返回
    return NextResponse.json(result, { status: 201 })
  })
}
```

### 動態路由
```typescript
// app/api/customers/[id]/route.ts
export async function GET(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  const customer = await getCustomer(parseInt(params.id))
  return NextResponse.json(customer)
}
```

## 錯誤處理

- **400**: 驗證錯誤 `AppError.validation()`
- **401**: 未認證 `AppError.unauthorized()`
- **403**: 無權限 `AppError.forbidden()`
- **404**: 未找到 `AppError.notFound()`
- **500**: 伺服器錯誤 `AppError.internal()`

## 關鍵約定

1. **統一包裝**: 所有handler使用 `withErrorHandling()`
2. **認證優先**: 第一步必須是 `authenticateRequest()`
3. **權限檢查**: 敏感操作使用 `checkPermission()`
4. **審計必記**: 寫操作必須 `auditLog.log()`
5. **類型安全**: 使用 `validateRequestBody<T>()`

## 依賴關係

- `lib/api/error-handler` - 統一錯誤處理
- `lib/auth` - 請求認證
- `lib/security` - 權限和審計
